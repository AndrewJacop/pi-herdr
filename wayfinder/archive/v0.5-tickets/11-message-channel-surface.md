## Question

The exact `message_orchestrator` / `message_agent` parameter and return surfaces for the herdr-native open message channel. Anchors already settled — do not re-open: charter item 7 (no broker, open fleet anyone↔anyone, all kinds via CLI convention, return address in `PI_HERDR_ORCHESTRATOR_PANE`, blocking ask/reply deferred post-v0.5); ticket `07`'s env-contract discipline (`PI_HERDR_*` = single-value scalars only; register: `PI_HERDR_ORCHESTRATOR_PANE`, `PI_HERDR_SPAWN_DEPTH`, `PI_HERDR_AGENT_LABEL`, `PI_HERDR_NO_SELF_REPORT`); ticket `06` (both tools in the visible-11); ticket `10` (shared `wait?: ms|true` vocabulary, handle|pane-id resolution chain, six-state status vocabulary, verify-before-act on `agent get`).

Decide: params for each tool (`message_agent` target addressing — handle|pane-id like `steer_agent`? `message_orchestrator` = text only via env return address?); the delivery mechanism — how a message physically reaches a pane child (steer-style text injection vs a herdr pane-metadata channel vs file+notice) and what is honestly promisable per kind; how a pi child's own pi-herdr surfaces an inbound message (injected prompt next-turn? a tool the child model calls?); return shapes; and whether/how an inbound message wakes or notifies a busy child (interplay with ticket `04`'s watcher and ticket `10`'s status flips). Also: what a non-pi child sees (CLI convention) without promising structure we can't enforce (charter 8 fidelity honesty).

## Resolution

HITL-grilled 2026-09-20 (wayfinder work-through session; overlay glitched mid-session, grilling continued in plain text). Anchors zoomed: charter 2/7/8, tickets `01`/`04`/`06`/`07`/`10`, `src/selfreport.ts` (v1 = state only), `src/tools/orchestration.ts` (`resolvePaneId`/`sendAgentPrompt`).

1. **One tool, not two — `message_orchestrator` is absorbed.** Mechanically both were "resolve a pane, inject text"; the split only bought an address source and a named speech act, neither worth a second tool. Charter item 7's two-tool naming is superseded by this ticket; the total contract (env return address, open fleet anyone↔anyone) is preserved.
2. **`message_agent = {target, text, submit? = true}` — target required, always explicit.** No omitted-param magic. Resolution chain (shared with get): exact pane-id → herdr name → spawn-registry handle → reserved roles, real names before reserved. **`"orchestrator"` is a reserved role handle** resolving via `PI_HERDR_ORCHESTRATOR_PANE` (spawn_agent sets it to the spawning pane's `HERDR_PANE_ID`). Reserved-but-unset (human-spawned session) → honest error: no orchestrator above you, answer in-conversation. Peer addressing is `list_agents` + handle.
3. **Delivery = text injection through the existing send machinery** (`resolvePaneId` + `sendAgentPrompt`). No pane-metadata channel, no file+notice, no new herdr surface. One code path.
4. **Envelope: `<agent-message from="X" to="Y">…</agent-message>`**, mirroring ticket `04`'s `<task-notification>` XML lineage. `from` = `PI_HERDR_AGENT_LABEL` → herdr pane name → pane-id string — spawner-declared, never verified, documented as convention. `to` = resolved label or the role `orchestrator`. **No child-side machinery**: the receiving extension never parses inbound text; the receiving *model* recognizes the tag (taught in tool description, and naturally present in spawn prompts).
5. **Physics-adaptive delivery — the one branch.** Verify-before-act already fetches the target's state: `blocked` → **raw text** into the ask-user overlay (the message *is* the answer; wrapping would pollute the recorded answer); `working`/`idle` → **enveloped**. Receipt reports `delivery: "message" | "answer"` so the model knows which happened.
6. **`steer_agent` is removed from the surface.** Its three jobs all route through message_agent: follow-up = enveloped message; blocked answer = the raw path; send-then-wait = `message_agent` + `get_agent_result(wait: true)` (no race — shared registry). Humans steering by hand type into the pane (steer was never for them). Charter item 2's quartet → **trio**: `spawn_agent` / `get_agent_result` / `message_agent` + pane-sync quartet. The `wait` vocabulary survives on **spawn + get only**; message is fire-and-forget — notifications carry completion. Ticket `10`'s steer half is superseded (update note appended there).
7. **Return shape** = `{delivered: true, target: <resolved pane-id>, state, delivery: "message"|"answer"}`. No read receipt, no reply handle — replies return as injected `<agent-message>` text or as the next completion notification. Honest ceiling in the description: *delivered to the pane ≠ consumed by the model*.
8. **State gates: none.** Working child → text queues natively. Blocked child → answer path (option-list caveat documented → `send_keys`). `gone` → error naming the handle, pointing at `list_agents` (ticket `10`'s get/steer asymmetry, carried to message).
9. **Wake/notify: zero new machinery.** Inbound to an idle pi child starts a turn natively (`agent_start` → self-report v1 already reports working); inbound to a working child queues. Ticket `04`'s watcher is unchanged — a messaged session-spawned child is simply seen working again, and its next completion re-fires the done notification. Upward replies land as injected text in the orchestrator's pane and trigger its turn the same way; two paths now reach the orchestrator (`04`'s in-process `pi.sendMessage`, external injection) but both land as prompts — one destination, no conflict. No new status in the six-state vocabulary.
10. **Pi-only scope ruling (the session's final cut): every v0.5 promise is pi-only.** No CLI-convention messaging docs (no audience), ticket `08`'s capability matrix is mooted (note appended there), per-kind validation rules and fidelity hedges are deleted. **`kind` survives as one unopinionated passthrough param** on `spawn_agent` — herdr's spawn works via `agent start --kind`, so the axis exists natively; a non-pi child gets exactly one honest line: *text in a pane, TUI-detected lifecycle, nothing else*. `default_kind` stays (the passthrough needs its default; it is pi). Charter items 7/8 amended accordingly.
11. **Fog patch dissolved — spawn-prompt etiquette needs no successor ticket.** Reply-up requires nothing passed down (reserved role + env); peer addressing is `list_agents`; the non-pi residual (teaching CLI conventions in non-pi spawn prompts) died with the pi-only ruling. Cleared from the map.

**Supersession ledger:** charter 2 (quartet→trio), charter 7 (two tools→one; "all kinds via CLI convention"→pi-only), charter 8 (fidelity hedges→one passthrough line), ticket `06` visible-11 → **visible-9** (spawn, get, message + quartet + save + list — steer gone, two message tools → one; update note appended), ticket `10` steer half (update note appended), ticket `08` matrix (mooted; note appended).
