## Resolution

HITL-grilled 2026-09-19 (wayfinder work-through session). Anchors zoomed: ticket `01`'s full resolution (handle fallback chain, blocked-terminal, wait vocabulary), ticket `04` (spawn registry, resultConsumed, `gone`), ticket `06` (visible-11, replacement), ticket `09` (verify-before-act), `src/tools/orchestration.ts` (`herdr_send_prompt`/`herdr_read_agent`/`herdr_delegate` — `agent read` sources, `agent prompt --wait`, `waitForStatus` event+poll), `src/selfreport.ts` (v1 bridges state only — no message channel exists).

1. **One wait vocabulary everywhere: `wait?: number | true`.** Shared across `spawn_agent`/`get_agent_result`/`steer_agent` — number = bounded ms (returns current state on expiry), `true` = until terminal (done/blocked/gone). `get_agent_result` default = snapshot, no blocking (the notification flow of ticket `04` already wakes the orchestrator post-terminal; bounded waits cover the mid-flight check without model-side polling loops). Spec teaches the vocabulary once.
2. **Six-state vocabulary; `done` = idle with an unconsumed result.** Statuses: `queued` (ticket `03` queue, no pane yet) | `working` | `idle` (resting, nothing new) | `done` (idle + unconsumed result) | `blocked` | `gone`. The spawn registry's last-seen-state map (ticket `04`) derives `done` from the working→idle transition; **`get_agent_result` itself flips `done`→`idle` once it returns the result — that fetch is the `resultConsumed` event** `04`'s notification suppression checks at send time. Extension-restart degradation is honest: registry lost → agent reports plain `idle`, result re-readable but unmarked; no reconstruction machinery.
3. **Result = the full last message, via adaptive tail read; no `lines` param.** The tool's contract is "the result", not "pane text": read `agent read --source recent-unwrapped` starting ~200 lines, re-read with a larger budget while `truncated`, bounded (~3 attempts / ~2000 lines). For a settled agent the complete tail ends with the full last message (leading TUI chrome included — honest). Raw pane-text control (source/lines/format) stays with `herdr_read_agent` in full mode. Overflow beyond the pane buffer → the existing write-to-file convention, stated in the tool description. Notification's ≤500-char preview (`04`) remains a notification-side truncation of this same text. Per-kind structural message parsing and self-report-v2 message channels both rejected for v0.5 (latter stays fog).
4. **`steer_agent` = `{target, text, submit?=true, wait?: ms|true}`, default fire-and-forget.** `submit?=true` mirrors `send_prompt` (compose-then-send stays reachable); `wait` completes the shared vocabulary for tight loops; the notification flow carries completion in the common case.
5. **No state gate: working and blocked both steerable.** Working child → text queues natively (pi and Claude Code queue mid-turn; kind-dependent elsewhere — stated honestly in the description). Blocked child → steer is the answer path per ticket `01`'s relay decision; the option-list caveat is documented in the description pointing at `herdr_send_keys` (kept visible by ticket `06`) — steer stays text-only, no keys param.
6. **`gone` asymmetry: valid status on get, error on steer.** `get_agent_result` on a vanished pane returns a normal (non-error) result `status: "gone"` + last-known registry metadata (handle, kind, duration, result text if a last capture exists) — the model reasons about it like any terminal state, matching `04`'s vocabulary. `steer_agent` on a gone pane errors (delivery impossible), naming the handle and pointing at `list_agents`. Both re-verify via `agent get` before reporting/actioning (ticket `09` verify-before-act). Unresolvable handle (registry lost AND herdr name lookup fails) = a distinct explicit `unknown handle` error on both.
7. **Implementation: the new pair wraps the old helpers; the old pair is unchanged.** One code path for pane I/O (`resolvePaneId`, `sendAgentPrompt`, `agent read` helpers); `get_agent_result` layers the registry/status/adaptive-read contract on top, `steer_agent` layers optional wait. `herdr_read_agent`/`herdr_send_prompt` stay byte-for-byte identical in full mode — no behavior change for existing users.

**Follow-on:** the herdr-native message pair (`message_orchestrator`/`message_agent`) named by charter item 7 and ticket `06`'s visible-11 had no owning ticket — created `11-message-channel-surface` (frontier; the fog's spawn-prompt etiquette item sharpens against it).
